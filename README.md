# Google Calendar As-Is / To-Be 발표 프로토타입

같은 일정을 처리하는 두 사용 흐름을 나란히 비교하는 소프트웨어공학 수업용 프로토타입입니다. 기존의 캘린더·입력 화면·지도·문서를 재사용하고, 왼쪽 As-Is와 오른쪽 To-Be를 독립된 앱으로 확장했습니다. UI는 제공된 한국어 Google Calendar 캡처를 기준으로 구성했습니다.

## 실행

**공개 사이트 주소: [Google Calendar As-Is / To-Be](https://happy0524.github.io/google-calendar-prototype/)**

GitHub Pages에서 정적 파일을 제공하므로 방문자의 컴퓨터에서 서버를 실행할 필요가 없습니다.

로컬 확인은 **프로젝트 폴더의 `index.html`을 브라우저로 여세요.** 설치·빌드·서버·로그인이 필요하지 않습니다. 문서와 CSS/JS가 함께 있어야 하므로 폴더 전체를 보관하세요. 모든 핵심 시연은 외부 API·CDN·웹 폰트 없이 `file://`에서 동작합니다.

- PC에서는 동일한 크기의 스마트폰 두 개와 공통 발표 제어를 표시합니다. 프레임 높이는 창 높이에 맞춰 조절합니다.
- 각 스마트폰 안에서 달력·일정 상세·입력창·지도·문서를 독립적으로 스크롤할 수 있습니다. 짧은 창에서도 프레임 하단을 화면 밖으로 밀어내지 않습니다.
- 900px 이하에서는 공통 제어를 아래에 배치하고, 620px 이하에서는 스마트폰을 위아래로 배치합니다.
- `Esc`는 현재 키보드 초점이 있는 앱의 열린 창을 닫거나 이전 화면으로 돌아갑니다. 문서 본문에 초점이 있으면 상단 뒤로 버튼을 사용하세요.

`documents/`는 앱 첨부파일이므로 폴더 전체가 필요합니다. `README.md`, `.gitignore`, `DEPLOY_FILES.txt`도 저장소 안내용으로 함께 올릴 수 있으며 앱 실행 자체에는 필요하지 않습니다.

### GitHub 웹 업로드와 Pages 설정

1. [happy0524/google-calendar-prototype](https://github.com/happy0524/google-calendar-prototype) 저장소를 엽니다. 이 프로젝트는 **공개 저장소 + `main` 브랜치**를 사용합니다.
2. 저장소의 **Add file → Upload files**에서 위 앱 파일을 업로드하고 커밋합니다. `index.html`과 `phone.html`이 저장소 최상위에 있고, 하위 폴더 구조가 유지되는지 확인하세요.
3. 숨김 파일인 `.nojekyll`도 최상위에 포함합니다. 업로드할 때 보이지 않으면 GitHub의 **Add file → Create new file**에서 `.nojekyll`이라는 빈 파일을 만들고 커밋하세요.
4. **Settings → Pages → Build and deployment**로 이동합니다.
5. **Source: Deploy from a branch**, **Branch: main**, **Folder: /(root)**를 선택하고 **Save**를 누릅니다. 브랜치 이름이 다르면 실제 업로드한 브랜치를 선택합니다.
6. 저장소의 **Actions**에서 Pages 작업 완료를 확인하고, **Settings → Pages → Visit site**에 표시되는 주소로 접속합니다.
7. [공개 사이트](https://happy0524.github.io/google-calendar-prototype/)에서 두 캘린더가 표시되는지 확인하고, 지도 비교·양쪽 문서 열람·오프라인 시연·오른쪽 AI 제안을 한 번 실행합니다.

서버 실행 명령, 패키지 설치, 빌드 명령, 별도 GitHub Actions YAML은 필요하지 않습니다. `.nojekyll`을 두어 정적 파일을 그대로 게시합니다. 위 설정은 GitHub의 [게시 소스 설정 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)와 [정적 사이트 생성 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site)를 기준으로 작성했습니다.

### 경로와 실행 방식

- CSS·JS·SVG·스마트폰 iframe은 `./...`, 예시 문서는 `./documents/...`, 문서 CSS는 `./document.css`를 사용합니다.
- `/css/...`처럼 사이트 루트로 시작하는 앱 경로, 컴퓨터의 절대 파일 경로, 특정 저장소 이름, 로컬 서버 주소에 의존하지 않습니다.
- 실제 Meet·Drive·Maps 주소로 요청하거나 외부 사이트로 이동하지 않습니다. Meet 주소는 화면에 표시하는 문자열입니다.
- 오프라인 토글은 데모 시나리오입니다. 공개 URL에서 처음 페이지를 불러올 때는 인터넷 연결이 필요하며, 실제 오프라인 캐시나 서비스 워커를 구현한 것은 아닙니다.

## 발표 순서

1. **전체 초기화**로 온라인·자동 제안 꺼짐 상태에서 시작합니다. 양쪽 월간 캘린더에서 같은 날짜를 선택하거나 일정을 따로 열어 독립 조작을 보여줍니다.
2. **지도 비교 시작**을 누릅니다. 양쪽에서 대표 일정이 열립니다. 왼쪽의 **지도에서 열기**로 Google Maps 화면에 들어가 장소·핀·길찾기를 확인합니다. 오른쪽에서는 일정 내부 지도로 같은 장소와 교통수단별 소요 시간을 확인합니다. 왼쪽의 **캘린더로 돌아가기**로 복귀합니다.
3. **첨부파일 비교 시작**을 누릅니다. 양쪽 대표 일정의 첨부 영역으로 이동합니다. 각각 **Google Drive에서 첨부**를 열고 같은 파일을 선택해 첨부합니다. 최근·내 드라이브·공유 문서함은 공통 예시 목록을 사용합니다.
4. 양쪽의 **회의 준비 자료**를 엽니다. 왼쪽은 Google Drive 화면, 오른쪽은 캘린더 내부 뷰어에서 **같은 문서**가 열립니다. 각각 뒤로 가기로 복귀합니다.
5. 오른쪽 ‘회의 준비 자료’의 **오프라인 저장 → 보관 기간 7일 → 저장**을 선택합니다. 약 1초의 진행 표시 후 저장 완료와 만료일을 확인합니다. 다른 첨부파일 하나는 저장하지 않은 채 둡니다.
6. 공통 **오프라인 시연**을 켭니다. 왼쪽 문서는 연결 필요 안내를 표시합니다. 오른쪽 저장한 문서는 열리고, 저장하지 않은 문서는 연결 필요 안내를 표시합니다. 이 토글은 실제 네트워크 설정을 바꾸지 않습니다.
7. 온라인으로 돌아와 **AI 제안 비교 시작**을 누릅니다. 왼쪽에서는 연필 버튼으로 알림이나 시간을 직접 수정합니다. **지금 AI 제안 띄우기 → 제안 확인 → 적용**으로 오른쪽만 변경되는 것을 보여줍니다. 오른쪽 팝업이 떠 있는 동안에도 왼쪽을 조작할 수 있습니다.
8. 필요하면 **오른쪽 AI 자동 제안**과 간격을 설정해 지도·첨부 시연 중 자동 제안을 보여줍니다. 마무리로 **전체 초기화**를 누릅니다.

비교 시작 버튼은 양쪽에서 같은 대표 일정 ID를 엽니다. 이후 각각 직접 조작할 수 있으며, 다른 쪽의 변경 내용을 복사하지 않습니다. 대표 일정을 삭제했다면 비교 시작 시 해당 앱에 그 일정만 복원합니다. 완전히 동일한 초기 내용으로 비교하려면 전체 초기화를 먼저 누르세요.

## 상태·이벤트·모달 분리

두 화면은 **같은 `phone.html`을 서로 다른 모드의 iframe으로 실행**합니다. 앱 코드는 공통이고, DOM·HTML id·전역 변수·이벤트 리스너·지도 인스턴스·스크롤·모달·타이머는 문서마다 분리됩니다. 한쪽의 `inert`와 모달 배경은 해당 스마트폰 안에서만 적용됩니다.

- 왼쪽: `DEMO_DATA.storageKey`에 `-comparison-asis-v2`를 붙인 키에 일정·상태 저장.
- 오른쪽: 같은 기준 키에 `-comparison-tobe-v2`를 붙인 키에 일정·오프라인 저장 상태 저장.
- 공통 설정: `calendar-course-comparison-controls-v2:<사이트 경로>`.

`DEMO_DATA.storageKey`에도 현재 사이트 경로를 포함합니다. 같은 GitHub 계정의 서로 다른 저장소 경로에서 데모 일정·저장 상태·설정이 섞이지 않습니다. 로컬 파일과 공개 사이트의 브라우저 저장소는 별도이므로 게시 후 처음에는 기본 상태로 시작합니다.

공통 제어는 지정된 iframe에 `postMessage`로 설정·시나리오 시작·초기화 명령만 전달합니다. 일정 데이터나 파일 저장 상태를 좌우로 복사하지 않습니다. 로컬 파일의 `origin` 제약을 고려해 발신 `Window`와 고정 채널을 확인합니다. AI 표시 명령은 오른쪽에만 전달하며 왼쪽 코드에서도 차단합니다.

## AI 제안 문구와 동작

`js/data.js`의 **`DEMO_DATA.suggestions` 배열**에서 `Math.random()`으로 선택합니다. 실제 AI 모델이나 일정 분석은 없습니다.

- 이동: 오른쪽 선택 일정의 알림을 50분 전으로 변경.
- 예약: 오른쪽 11월 12일 팀 저녁 약속에 하루 전 예약 확인 알림 추가.
- 접수: 오른쪽 11월 2일 오전 9시에 자격증 접수 확인 일정 추가. 반복해도 중복 생성하지 않습니다.
- 충돌: 오른쪽 대표 팀 회의를 오후 4:30–6:00으로 변경.

자동 제안은 오른쪽 상세에서 지도·첨부와 상호작용한 뒤에만 활성화됩니다. 마지막 상호작용 후 최소 4.5초를 두고, 2분 동안 활동이 없으면 표시하지 않습니다. 파일 선택·저장 설정·문서 열람·다른 팝업 중에는 표시하지 않고, 닫은 뒤 다음 간격에 확인합니다. 타이머는 오른쪽에 하나만 유지하며, 자동 제안 끄기·숨겨진 탭·전체 초기화에서 중지됩니다. 수동 제안도 다른 창 위에 중첩되지 않습니다.

## 구현 범위

모든 장소·지도·경로·평점·문서·AI 제안은 준비된 발표 데이터입니다. 실제 Google 로그인, Calendar·Maps·Drive·Meet·LLM API, 백엔드, DB, 초대 전송, 예약 조회·접수, 파일 업로드·다운로드·압축은 구현하지 않았습니다. 왼쪽의 외부 앱 전환도 스마트폰 안의 화면 전환입니다. 외부 서비스 변경과 공개 배포는 없습니다.

## 실제 실행 검증 결과

Chromium에서 서버 없이 `file://`로 실행했습니다. 양쪽 스마트폰을 실제로 클릭하는 자동화 검사와 화면 캡처로 확인했습니다.

| 요청 항목                             | 실행 결과                                                                                                                                    |
| ------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. 같은 일정 각각 열기                | 확인: 같은 초기 데이터와 대표 일정, 독립 날짜 선택·일정 열기                                                                                 |
| 2. 왼쪽 Maps·Drive 이동과 복귀        | 확인: 프레임 안에서 전환되고 각각 캘린더로 복귀                                                                                              |
| 3. 오른쪽 일정 내 지도·문서           | 확인: 지도 확대·축소·드래그·핀·리뷰·교통수단별 경로, 내부 문서 뷰어                                                                          |
| 4. 오프라인 차이                      | 확인: 왼쪽 연결 필요, 오른쪽 저장 파일 열림·미저장 파일 연결 필요, 저장 상태 공유 없음                                                       |
| 5. 오른쪽 AI가 왼쪽 조작을 방해하는지 | 확인: 오른쪽 제안 팝업이 열린 동안 왼쪽에서 수정·저장 가능                                                                                   |
| 6. 데이터·모달·스크롤 독립성          | 확인: 각자 등록·수정·취소·삭제, 파일 선택 체크, 모달 닫기, 화면 이동과 스크롤이 다른 쪽에 영향 없음                                          |
| 7. 반복 초기화와 타이머               | 확인: 저장 진행 중 초기화가 완료 콜백을 취소, 5회 반복 초기화 후 자동 제안 한 개만 표시, 문서 열람 중 억제·닫은 후 재개, 초기화 후 제안 없음 |
| 8. 노트북 화면 잘림                   | 확인: 1440×900, 1366×768, 1280×720, 1024×768, 1280×600에서 좌우 동일 크기·완전 노출·전체 페이지 가로/세로 넘침 없음                          |

추가로 양쪽 일정 양식의 제목·날짜·시간·장소·참석자·알림·Meet 표시, 네 종류 AI 제안의 오른쪽 상태 반영, 새로고침 후 독립 데이터 유지, 런타임 외부 HTTP(S) 요청 및 처리되지 않은 JavaScript 오류가 없음을 확인했습니다. 자동 제안 간격과 장시간 동작은 브라우저의 가상 시계로 검사했습니다.

**미확인:** Safari·Edge 및 실제 iPhone/Android 기기. 날짜·시간 선택기를 펼친 화면은 운영체제·브라우저의 기본 UI이므로 모양이 다를 수 있습니다. 실제 Google 서비스 연결·네트워크 전환·파일 다운로드는 구현 범위에 포함되지 않습니다.

## GitHub Pages 배포 경로 검증

정적 파일 16개를 목록과 대조했고, `.nojekyll`이 빈 파일인지 확인했습니다. 런타임 코드·HTML에서 특정 컴퓨터의 절대 경로와 로컬 서버 주소에 대한 의존은 없으며, 모든 앱 리소스 연결은 상대 경로입니다.

GitHub Pages의 저장소 하위 주소를 재현하는 임시 HTTP 정적 호스팅에서 Chromium으로 다음을 실행했습니다. 검사 뒤 임시 서버는 종료했습니다. 이 서버는 개발 검증에만 사용했으며 방문자가 실행할 프로그램은 없습니다.

- `/sample-repository/`: CSS·JS·SVG·양쪽 앱 iframe과 문서 CSS까지 모두 정상 응답.
- 왼쪽 Maps·Drive 전환과 복귀, 오른쪽 지도·내부 문서 열람, 동일 문서 로드, 저장 파일과 미저장 파일의 오프라인 시나리오, 오른쪽 AI 적용 정상.
- `/other-repository/`: 같은 도메인에서도 일정·첨부 저장·공통 설정이 다른 저장소와 분리됨.
- `/courses/calendar-comparison/`: 추가 하위 폴더에서도 문서와 스타일 정상 로드.
- 검증한 브라우저 흐름에서 JavaScript 오류, 404 응답, 실패한 리소스 요청, 외부 API·CDN 요청 없음.

위 내용은 로컬 배포 경로 검증 기록입니다. 공개 사이트는 [게시 주소](https://happy0524.github.io/google-calendar-prototype/)에서 확인할 수 있습니다. **별도 미검증 환경:** Safari·Edge와 실제 모바일 기기.
